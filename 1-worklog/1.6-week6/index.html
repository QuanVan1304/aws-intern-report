Week 6 Achievements:

  • Deployment Status: The Endpoint (rossmann-forecasting-endpoint) successfully transitioned to the InService state via the rossmann-config-1785086724 configuration file.
  • Quality Gate Metrics:
    • Smoke Test: The API successfully returned a properly formatted JSON response ({"predicted_sales": [5267.64]}).
    • Real-world Validation: For Store 1, the actual historical sales were 5518.00; the API predicted 5780.13. This resulted in an error margin of merely 4.75%, excellently passing the standard acceptable threshold of 15.0%.
  • Completed Architecture: The integration flow spanning API Gateway, Lambda, and the Endpoint functioned flawlessly, returning HTTP 200 OK.

Technical Notes & Deep-Dive Troubleshooting:

1. Inference Logic Corrections:

  • Issue (Overflow/Nonsense Predictions): The endpoint returned numerical overflows. The root cause was identified within inference.py, where np.expm1() was being applied to the output. However, the specific XGBoost model deployed had been trained on raw Sales data (bypassing the log1p transformation).
  • Solution: The predict_fn was modified to explicitly remove the np.expm1() transformation, allowing the API to return the direct output of model.predict(X).

2. Container & Environment Troubleshooting:

  • ValidationException (ECR Permissions): Deployment failed because the Container Image URI was hardcoded with a us-east-1 Account ID. Solution: Consulted AWS documentation and re-routed the URI to the correct ap-southeast-1 registry (121021644041.dkr.ecr.ap-southeast-1.amazonaws.com/sagemaker-xgboost:1.7-1).
  • ModelError (HTTP 500): The API crashed upon invocation. This occurred because the model was trained with a newer XGBoost version than what the 1.7-1 serving container supported. Solution: Enforced strict version synchronization between the training environment and the serving container.

3. Cost Optimization & Cleanup Script Vulnerability:

  • Data Leakage Prevention: During real-world testing (build_real_features.py), the extraction logic mathematically guaranteed that lag features (sales_lag_*, rolling_*) were calculated strictly from historical data prior to the prediction date, completely eliminating data leakage.
  • Cleanup Script Bug: The automated cleanup.py script relied on the filter NameContains="rossmann-xgboost". This logic inadvertently skipped models generated by the Pipeline named rossmann-pipeline-xgboost-* because the substring was not contiguous.
  • Solution: Identified the ghost resources and manually purged all remaining Models, Endpoint Configs, and Endpoints using AWS CLI commands (list-models, list-endpoints). A final verification confirmed all three lists were completely empty, ensuring 0$ in lingering cloud infrastructure costs.
