# AWS MLOps Platform for Sales Forecasting
## Automated Sales Forecasting System for Rossmann Store Chain on AWS

### 1. Executive Summary
The "AWS MLOps Platform for Sales Forecasting" project is designed to build an end-to-end machine learning system to predict future sales for the Rossmann store chain. Instead of training and deploying models manually, this platform leverages the power of AWS SageMaker Pipelines to automate the entire model lifecycle (CI/CD). Combined with a Serverless architecture (AWS Lambda, API Gateway), the system provides a real-time forecasting API with optimal operational costs, low latency, and high scalability.

### 2. Problem Statement
**Current Status:**
The sales forecasting process at retail chains often relies on manual, local model training. This leads to fragmented data management, difficulties in updating the model with new data, and the lack of a standardized API system to integrate forecasting results into existing business management applications.

**Proposed Solution:**
The project will build a comprehensive MLOps pipeline. Historical data is preprocessed and stored on Amazon S3. AWS SageMaker Pipelines will handle the automated training of the XGBoost model. Once the model meets the required standards (Quality Gate), it will be deployed to a SageMaker Endpoint. Finally, the communication layer will be built using Amazon API Gateway and AWS Lambda, allowing users or client applications to query forecasting results via an intuitive web interface.

**Benefits and Return on Investment (ROI):**
The solution completely eliminates manual operations in updating and deploying machine learning models. By utilizing a Serverless architecture for the API layer and a pay-as-you-go pricing model for SageMaker, the system helps minimize operational costs. The high accuracy of the model enables the business to optimize its supply chain, reduce excess inventory, and improve business efficiency.

### 3. Solution Architecture
The system utilizes core AWS services to create a continuous data flow from storage and training to forecast serving, strictly adhering to the security and infrastructure principles of the **AWS Well-Architected Framework**.

#### 3.1. Overview of AWS Services Used
- **Amazon S3:** Stores training data, test data, and Model Artifacts generated by the system (SSE-KMS encryption).
- **AWS SageMaker Pipelines:** A service that automatically orchestrates the model training lifecycle (CI).
- **AWS SageMaker Endpoint:** The host server for the model to serve real-time predictions (CD), supporting Auto Scaling and Multi-AZ.
- **AWS Lambda:** A Serverless function handling intermediate logic, applying the principle of least privilege (Least-privilege IAM Role).
- **Amazon API Gateway:** A REST API gateway that receives client requests, integrated with Cognito authentication.
- **AWS WAF (Web Application Firewall):** A firewall layer protecting the entire API tier, implementing Rate Limiting rules and mitigating network attacks.
- **VPC & Private Subnet:** Completely isolates core computing resources (Lambda, SageMaker) from the public Internet.
- **VPC Endpoint (PrivateLink):** Creates a private connection on the AWS backbone network for `sagemaker-runtime` traffic.
- **Amazon CloudWatch:** Asynchronously collects Execution Logs, monitors Data Drift, and triggers system performance alarms.

#### 3.3. Detailed Architectural Layer Breakdown

1. **Public / Edge Layer:**
   - **Client:** Sends real-time forecasting requests via HTTPS protocol.
   - **AWS WAF:** Blocks malicious requests, prevents DDoS attacks, and applies rate-limiting rules.
   - **Amazon API Gateway:** Receives filtered requests from WAF, performs user authentication, and routes requests to the compute tier.

2. **Private Network & Compute Layer:**
   - **VPC & Private Subnet:** All logic processing and computing components are isolated within an independent Virtual Private Cloud.
   - **AWS Lambda:** Receives data from API Gateway, preprocesses the request payload, and invokes the forecasting endpoint.
   - **VPC Endpoint (`sagemaker-runtime`):** Ensures that the communication flow between Lambda and the SageMaker Endpoint runs 100% on the AWS internal network without traversing the public Internet.
   - **SageMaker Endpoint:** Utilizes the power of the trained XGBoost model to deliver forecasting results, configured with Multi-AZ to ensure high availability.

3. **Storage & Control-Plane Layer:**
   - **Amazon S3:** The SageMaker Endpoint proactively pulls quality-assured model artifacts (`.tar.gz`) from S3 to load into memory.
   - **Amazon CloudWatch:** Asynchronously receives *Execution Logs* from Lambda and *Async Logs / Data Drift* from the SageMaker Endpoint for continuous model management and development.

### 4. Technical Implementation
**Expected Deployment Phases:**
- **Phase 1 (Weeks 1-2):** Data preprocessing (Feature Engineering) and setting up the S3 storage environment.
- **Phase 2 (Weeks 3-4):** Building the baseline model (XGBoost) and evaluating deep learning architectures (LSTM).
- **Phase 3 (Weeks 5-6):** Building SageMaker Pipelines, packaging the Endpoint, and developing the Serverless API.
- **Phase 4 (Weeks 7-8):** Setting up the monitoring system (CloudWatch, Data Drift) and resource housekeeping.

**Technical Requirements:**
- Programming Language: Python 3.x.
- Core Libraries: `boto3`, `sagemaker==2.257.5`, `xgboost`, `pandas`, `scikit-learn`.
- Interface (Demo UI): HTML, CSS, JavaScript (Fetch API).

### 6. Budget Estimation
The project is optimized to operate on the most economical budget possible via the AWS Free Tier and automated resource deletion scripts.
- **Amazon S3:** ~$0.10/month for storing a few hundred MBs of data.
- **SageMaker Training Job (`ml.m5.large`):** Pay-per-minute billing, estimated ~$1-2 for the entire development process.
- **SageMaker Endpoint (`ml.t2.medium`):** ~$0.05/hour (Turned on only for testing/demos; a cleanup script will be used to destroy the instance).
- **API Gateway & Lambda:** Entirely within the Free Tier (under 1 million requests/month).
*Total estimated cost for the internship duration: Under $5.00.*

### 7. Risk Assessment
- **AWS Quota Risk (High):** New accounts might have a Training Job quota of 0. 
  *Mitigation Strategy:* Submit a quota increase request via Service Quotas in the very first week.
- **SDK Library Conflict Risk (Medium):** New SDK updates could cause pipeline failures. 
  *Mitigation Strategy:* Implement Dependency Pinning in the `requirements.txt` file.
- **Budget Overrun Risk (Low):** Forgetting to turn off the Endpoint leading to hourly charges. 
  *Mitigation Strategy:* Write an automated `cleanup.py` script to tear down all active resources.

### 8. Expected Outcomes
- **Technical:** Successfully build an enterprise-grade MLOps system seamlessly integrating Model Training infrastructure and a Serverless API.
- **Accuracy:** The model achieves a Mean Absolute Percentage Error (MAPE) of under 15%, reliable enough for business predictions.
- **Long-term Value:** The architecture can be reused as a template for other time-series forecasting problems in the future.
